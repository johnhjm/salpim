# 살핌 점검 절차

살핌은 고객에게 "매주 월요일 아침 6가지를 점검한다"고 약속한다. 그래서 살핌 사이트 자신도 같은 6가지를 매주 점검한다. 고객 사이트는 이 문서의 "고객 사이트" 절에 적는다.

원칙
- 문제가 없으면 "✅ 이상 없음" 한 줄. 길게 쓰지 않는다.
- 작은 문제(오타, 깨진 링크, 어색한 줄바꿈)는 고치고 알린다. 구성·문구·가격·디자인을 바꾸는 일은 Ha님 확인 없이 하지 않는다.
- Ha님은 개발자가 아니다. 결과는 쉬운 한국어로 쓴다.
- 사이트에 실명·사진·회사 이름을 넣지 않는다. '무제한'이라는 말을 쓰지 않는다.

## 점검 도구

`tools/check.mjs` 가 브라우저(Playwright)로 첫 페이지와 샘플 4개를 휴대폰 320·360·390px, PC 1200px로 열어 아래를 본다.

| 약속한 항목 | 실제로 보는 것 |
|---|---|
| ① 사이트 접속 | 5개 페이지가 모두 열리는지, 실제 사이트는 4초 안에 뜨는지 |
| ② 휴대폰 화면 | 화면 폭 4가지에서 가로로 넘치는 것, 오류 |
| ③ 링크와 사진 | 쪽 안 이동 링크, 사이트 안 링크, 바깥 링크, 사진이 뜨는지 |
| ④ 전화·지도·예약 버튼 | 상담 구역의 연락처가 연결돼 있는지, 번호·이메일 형식 |
| ⑤ 인증서와 도메인 | 보안 인증서 남은 날 (14일 아래면 문제) |
| ⑥ 지난 내용 | 첫 화면 리포트 날짜, 올해 점검표 칸 수, 지난 날짜가 적힌 글, '무제한' |
| 기능 동작 | 가격 합계 바꾸기, 질문 펼치기, 보고 문자, 다크 모드, 샘플의 영업 중·진료 안내판·실적 거르기, 샘플 표시 |

- 내 컴퓨터(저장소의 `site/`) 점검: `node tools/check.mjs` (화면 사진까지: `--shots=/tmp/shots`)
- 실제 사이트 점검: GitHub Actions "전체 기능 점검"(`.github/workflows/check.yml`)이 매주 월요일 08:10(한국 시간)에 돌고 결과를 `tools/data/check-results.json` 에 저장한다. Claude 작업 환경에서는 바깥 사이트를 직접 열 수 없어서 이 방법을 쓴다.
- 연락처를 넣기 전에는 ④가 "연락처가 비어 있음"으로 1건 실패하는 것이 정상이다.

## 주간 점검 (매주 월요일 아침, 예약 작업 "살핌 주간 점검")

1. `git pull` 뒤 `tools/data/check-results.json` 을 읽는다. `kstDate` 가 오늘(한국 날짜)이 아니면 Actions가 아직 안 돈 것이다.
   - `gh workflow run check.yml -R johnhjm/salpim` 또는 `gh api -X POST repos/johnhjm/salpim/actions/workflows/check.yml/dispatches -f ref=main` 으로 한 번 실행하고, 3~5분 뒤 `git pull` 해서 다시 본다.
   - 실행할 수 없거나 결과가 끝내 없으면 "실제 사이트 점검 결과 없음(이유)"이라고 쓰고 2번의 내 컴퓨터 점검 결과로 대신한다. 없는 결과를 있는 것처럼 쓰지 않는다.
2. 저장소 상태 점검: `node tools/build.mjs` 를 돌리고 `git status --short site/` 가 비어 있는지(원본과 배포본이 같은지) 본 다음 `node tools/check.mjs` 를 돌린다.
3. 최신 배포 확인: `gh api repos/johnhjm/salpim/commits/main/check-runs --jq '.check_runs[] | "\(.name): \(.status) \(.conclusion)"'` 에서 Cloudflare Pages 가 `completed success` 인지 본다. (점검 결과만 저장한 커밋은 배포를 건너뛰므로, 결과가 없으면 사이트 파일을 바꾼 마지막 커밋으로 본다.)
4. 도메인: `tools/build.mjs` 의 `SITE_URL` 이 비어 있으면 "도메인 미정"이라고 한 줄. 정해진 뒤에는 CLAUDE.md 에 적힌 도메인 만료일이 60일 안이면 알린다.
5. `tools/check-log.md` 표 맨 위에 오늘 날짜 줄을 더하고(통과 수, 문제, 조치) 커밋(한국어)·푸시한다. 이 기록이 "매주 점검했다"는 근거다.
6. 결과 보고 (3~6줄)
   - 첫 줄: `✅ 이상 없음 — ○개 항목 모두 정상` 또는 `⚠️ 문제 ○건`
   - 문제가 있으면: 무엇이, 왜, 고쳤는지, Ha님이 할 일이 있는지
   - 마지막 줄(있을 때만): Ha님이 할 일 (예: 도메인 구입, 연락처 정하기)

## 고객 사이트

살핌 사이트 점검이 끝나면 아래 고객 사이트를 차례로 점검한다. 살핌 쪽에 문제가 있어도 건너뛰지 않는다. 고객마다 저장소가 따로 있고, 점검 방법은 그 저장소의 `tools/health-check.md` "주간 점검"에 적혀 있다. 결과는 그 저장소의 `tools/check-log.md` 에 남긴다(관리 대장을 만들면 거기에도). 문제가 보이면 그날 Ha님께 알리고 고객에게 보낼 문자 초안을 같이 드린다(client-homepage 스킬 7번).

| 고객 | 저장소 | 주소 | 넣은 날 | 메모 |
|---|---|---|---|---|
| 비추미안경 | johnhjm/client-bichumi | https://bichumi.pages.dev | 2026-11-25 | 지인 무료 고객(수금 없음). 시안 단계, 도메인 미정. 자동 점검은 월요일 08:20 |

새 고객을 더할 때: 이 표에 한 줄, 고객 저장소에 `tools/weekly.mjs`·`.github/workflows/check.yml`·`tools/health-check.md`·`tools/check-log.md`(비추미안경 것을 본떠서), 그리고 예약 작업 "살핌 주간 점검"의 고객 목록에 저장소 이름을 더한다.

## 월간 (매월 1일, 고객이 생기면 예약)

수금 대상, 미수, 도메인·약정 만료 60일 이내, 고객별 월간 관리 보고 문자 초안(client-homepage 스킬 7번). 고객이 없는 동안은 만들지 않는다.
